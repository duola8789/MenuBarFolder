# update-check Specification

## Purpose
让用户在不离开应用的情况下得知是否有新版本：由用户主动触发一次版本检查，比较当前版本与最新发布版本，并把结果（有新版本 / 已是最新 / 检查失败）就地呈现，同时明确不自动下载或替换应用。

## Requirements

### Requirement: 用户在 About 页触发版本检查

设置窗口的 About 页 SHALL 提供「Check for Updates」控件，并始终显示当前运行版本号。控件被点击时，应用 SHALL 向本项目的 GitHub 最新发布页面发起一次请求，跟随其重定向到具体的发布标签页，从该页面地址取得最新发布标签与发布页面地址。

检查进行中时，控件 SHALL 处于不可重复触发的状态并给出进行中提示。请求 SHALL 设置不超过 10 秒的超时。

#### Scenario: 点击后发起一次检查
- **WHEN** 用户点击「Check for Updates」
- **THEN** 应用发起一次最新发布查询，控件变为进行中且不可再次点击
- **AND** 请求结束后控件恢复可点击

#### Scenario: 重复点击不会叠加请求
- **WHEN** 检查尚未结束，用户再次点击控件
- **THEN** 应用不发起第二次请求

### Requirement: 版本比较规则

应用 SHALL 将远端发布标签去除可选的前导 `v` 后，与当前版本按点号分段的纯数字逐段比较，缺位按 0 处理；仅当远端版本严格大于当前版本时判定为有更新。

#### Scenario: 远端版本更高
- **WHEN** 当前版本为 `1.5.1`，远端标签为 `v1.5.2`
- **THEN** 判定为有更新

#### Scenario: 分段按数值而非字典序比较
- **WHEN** 当前版本为 `1.5.9`，远端标签为 `v1.5.10`
- **THEN** 判定为有更新

#### Scenario: 远端版本相同或更低
- **WHEN** 远端版本等于或低于当前版本
- **THEN** 判定为已是最新

### Requirement: 检查结果呈现

检查结束后应用 SHALL 向用户明确呈现以下三种结果之一：

- 有更新：显示远端版本号，并提供可打开发布页面的「Download」动作；
- 已是最新：显示当前版本号已是最新；
- 失败：显示检查失败及原因（网络错误、响应格式无效、版本无法解析）。

应用 MUST NOT 在存在新版本时自行下载或替换正在运行的应用；「Download」仅打开系统浏览器中的发布页面。

#### Scenario: 有更新时打开发布页
- **WHEN** 检查结果为有更新，用户选择「Download」
- **THEN** 系统浏览器打开该发布的页面，应用本身不被替换或退出

#### Scenario: 已是最新
- **WHEN** 检查结果为已是最新
- **THEN** 应用提示当前版本已是最新，不提供下载动作

#### Scenario: 检查失败
- **WHEN** 网络请求失败、超时或响应无法解析
- **THEN** 应用提示检查失败及原因，不改变版本号显示

### Requirement: 网络行为边界

版本检查 SHALL 仅在用户每次显式点击控件时发生。应用 MUST NOT 在启动时、定时或后台自动发起版本检查。请求 SHALL 只发往本项目的 GitHub Releases 页面，MUST NOT 向任何第三方端点发送用户数据或使用统计。检查结果 MUST NOT 被持久化用于后台行为。

#### Scenario: 启动不联网
- **WHEN** 应用启动并保持运行，用户未点击检查控件
- **THEN** 应用不发起任何网络请求

#### Scenario: 请求目标固定
- **WHEN** 用户触发检查
- **THEN** 请求只发往本项目的 GitHub Releases 页面，不携带用户标识或统计信息
